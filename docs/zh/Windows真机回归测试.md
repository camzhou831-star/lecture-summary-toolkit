# Windows 真机回归测试(视频模式 + 字幕模式 + 网页版)

> 写给帮忙在 Windows 电脑上测试的同学。代码已经改好(分支 `windows-subtitle`,PR #1),GitHub 上的 Windows CI(含视频模式完整流程)也通过了;这份清单是在**真实 Windows 电脑**上从头到尾走一遍,看普通用户会卡在哪。**视频模式是重点。**
> 你只需要测试、记录,不用改代码。遇到问题按最后一节的格式记下来发给我。
>
> **10-18 更新**:新增「第二部分 B:新的输入方式」(N0–N6),第 1 步、V1、V2 的预期和第三部分的检查也改了。之前已经测过的步骤不用重测,拉最新的 `windows-subtitle` 分支(或用我新发的测试包)后,测 N0–N6 和第三部分即可。

## 测试范围

- **重点**:视频模式(把下载好的录播视频放进来 → 转写 + 抓幻灯片 → AI 写总结)。
- **也要测**:字幕模式、网页版提示词。

## 准备

1. 一台 Windows 10 或 11 电脑。记下:系统版本、系统语言(中文 / 英文)、用户名里有没有中文。
2. 拿到测试包(我发给你的 zip,或者仓库里 `windows-subtitle` 分支的代码)。**用资源管理器右键"全部解压缩"**,不要用命令行。解压后打开看一眼:`工具`、`课程视频` 这类中文文件夹名是否正常显示。
3. 测试用的字幕:把仓库里的合成示例 `examples\demo\课程视频\DEMO1001 - 01 Jan 26-s1-demo.srt` 复制到桌面,改名为 `captions.srt`(故意让文件名看不出课程和日期)。下面的 `<合成字幕.srt>` 都指它。
4. 装一个 AI 应用:Claude Code / Codex / Gemini CLI 任选一个,用你自己的账号登录。

## 第二部分:视频模式(重点)

测试视频:仓库里的合成示例 `examples\demo\课程视频\DEMO1001 - 01 Jan 26-s1-demo.mp4`(2 分钟)。跑通后**再用一节你自己的真实录播**(1–2 小时)测一次,记下总用时;真实录播只在你自己电脑上跑,产物不要发出来。

| # | 操作 | 应该看到 |
|---|---|---|
| V1 | `lsk.cmd doctor --video` | 列出 ffmpeg、whisper-cli、tesseract、Pillow、whisper 模型,缺的每项后面有安装命令(winget / `lsk setup` / pip)。缺 Pillow 或 pypdf 时,python 那行下面多一行"下面的 Python 包…检查的是这个 Python",pip 命令写成 `"C:\...\python.exe" -m pip install --user pillow`(用的是第一行那个 Python 的完整路径,不是 `py`) |
| V2 | 按提示装:`winget install Gyan.FFmpeg`、`winget install UB-Mannheim.TesseractOCR`,Pillow / pypdf **照抄 doctor 给的 pip 命令** | 都装成功,装完 doctor 里 Pillow 变成 ✅;记下哪一步要管理员权限、有没有弹窗。winget 报网络错误(如 `0x80072efd`,常见于代理失效或地区限制)时,Tesseract 改从 https://github.com/UB-Mannheim/tesseract/releases 下载安装包、装到默认位置,并在报告里写明是手动装的 |
| V3 | **不关当前窗口**,再跑 `lsk.cmd doctor --video` | ffmpeg 和 tesseract 变成 ✅(刚装完 PATH 还没刷新,工具应该自己找得到) |
| V4 | `lsk.cmd setup` | 从安装包解压 GPU 版 whisper.cpp(Vulkan),再下 CPU 兜底版(约 8 MB)和模型(约 1.6 GB,有进度百分比);最后做 GPU 自检(用示例视频前 45 秒):逐行打印 `✅/❌ gpu…: <显卡名> <转写开头>`,结尾 `✅ GPU 转写: <你的显卡名>(设置: gpu…)`。**把自检这几行原样发我**(哪一档通过对我们很有用);如果结尾是"没能用上显卡",再附上显卡型号和驱动版本 |
| V5 | 把示例视频复制到 `课程视频\`,`lsk.cmd run "DEMO1001 - 01 Jan 26-s1-demo.mp4"` | 依次出现 [1/5]…[5/5],最后 `全部完成`;`画面\DEMO1001 - 01 Jan 26-s1-demo\` 里有几张 `t000xxs.jpg` |
| V6 | 记事本打开 `课程视频\DEMO1001 - 01 Jan 26-s1-demo.grounded.md` | 有英文转写(含 "prime path"),有 `📄 t=… p2/6 …` 这样的幻灯片行 |
| V7 | 真实录播:放进 `课程视频\`,`lsk.cmd run "<文件名>.mp4"` | 能跑完;记下总用时、显卡型号、CPU 型号、内存;转写那行显示 `GPU: 开` 后有没有出现"改用 CPU(--no-gpu)重试"(出现说明 GPU 版没跑起来,把它上面的报错原文发我);任务管理器里"GPU"的 CUDA 占用有没有上去 |
| V8 | 如果你的用户名或文件夹路径里有中文:在那个路径下再跑一次 V5 | 照样跑完(whisper.cpp 读中文路径是已知风险点) |

## 第二部分 B:新的输入方式(10-18 新增)

背景:Mac 上的测试发现,很多人从 LMS 拿到的是没有时间戳的 `.txt` 文字稿,或者字幕和视频分开下载、留在别的文件夹里。现在 `lsk run` 能直接处理这些情况,要在 Windows 上确认一遍。

**准备**:在桌面建一个文件夹 `输入测试`,把仓库里这三个示例文件复制进去:
`examples\demo\课程视频\` 下的 `DEMO1001 - 01 Jan 26-s1-demo.mp4`、`.srt`、`.txt`(这份 `.txt` 是没有时间戳的纯文字,用来模拟 LMS 导出的文字稿)。

**每一步开始前先清掉旧产物**(否则会直接用 V5 留下的字幕,测不出来):删掉工具文件夹里 `课程视频\DEMO1001 - 01 Jan 26-s1-demo.*` 这几个文件,以及 `画面\DEMO1001 - 01 Jan 26-s1-demo\` 文件夹。另外,**视频每跑一次就会被移进 `课程视频\`**(这是正常的),所以下一步开始前要从 `examples\demo\课程视频\` 重新复制一份 `.mp4` 到 `<输入测试>`(N3、N5 按各自说明放)。下面的 `<输入测试>` 指 `C:\Users\<你>\Desktop\输入测试`。

| # | 操作 | 应该看到 |
|---|---|---|
| N0 | 关掉所有窗口,在资源管理器里打开 `lecture-summary-toolkit` 文件夹,在地址栏输入 `cmd` 按回车,运行 `lsk.cmd doctor` | 打开的 cmd 已经在工具文件夹里,doctor 正常运行(README 里新写的进目录方法,确认这个办法在 Windows 上可行) |
| N1 | 新建文件夹 `<输入测试>\只有文字稿`,只放 `.txt`;`lsk.cmd run "<输入测试>\只有文字稿\DEMO1001 - 01 Jan 26-s1-demo.txt"` | 退出并列出 3 个办法(下载字幕 / 配同名视频或 `--video` / 只用文字稿没有时间线);中文不乱码。**不应该**是旧的那句"只支持 .srt / .vtt 字幕或视频文件" |
| N2 | (先清旧产物)`lsk.cmd run "<输入测试>\DEMO1001 - 01 Jan 26-s1-demo.txt"`,这次 `<输入测试>` 里**先把 `.srt` 挪走**,只留 `.txt` 和 `.mp4` | 开头两行:`文字稿没有时间戳,改用视频 … 转写拿时间` 和 `文字稿另存 … 课程视频\DEMO1001 - 01 Jan 26-s1-demo.lms.txt`;然后是 [1/5] **转写**(真的跑 whisper,不是"已有 srt 跳过")…[5/5] `全部完成`。完成后 `课程视频\` 里同时有 `.lms.txt`(内容和原文字稿一样)和 whisper 生成的 `.txt`;视频被移进了 `课程视频\`;`<输入测试>` 里的原文字稿还在 |
| N3 | (先清旧产物)从 `examples` 复制一份视频到 `<输入测试>`,改名成 `别的名字.mp4`;`lsk.cmd run "<输入测试>\DEMO1001 - 01 Jan 26-s1-demo.txt" --video "<输入测试>\别的名字.mp4"` | 能跑完,`.lms.txt` 按视频的名字存(`课程视频\别的名字.lms.txt`)。因为文件名看不出课程,最后一行总结路径里写 `<单元代码>`,这是正常的。测完删掉 `课程视频\别的名字.*` 和 `画面\别的名字\` |
| N4 | (先清旧产物)`<输入测试>` 里放 `.mp4` 和同名 `.srt`;`lsk.cmd run "<输入测试>\DEMO1001 - 01 Jan 26-s1-demo.mp4"` | 先出现 `找到同名字幕 …,复制到 课程视频/,跳过 whisper 转写`;[1/5] 显示 `已有 … .srt,跳过`;整体几秒就完成;`<输入测试>` 里的 `.srt` 还在(是复制,不是移走) |
| N5 | (先清旧产物)把 `.srt` 和 `.mp4` 复制到 `C:\Users\<你>\Downloads\`;在工具文件夹里只写文件名:`lsk.cmd run "DEMO1001 - 01 Jan 26-s1-demo.mp4"` | 能在 Downloads 里找到视频,同样提示找到同名字幕并跳过转写 |
| N6 | 只写一个不存在的文件名:`lsk.cmd run "不存在.srt"` | 报错说找不到,并写明查过当前目录、`课程视频/`、`~/Downloads/` |

N2 那步把总用时和 [1/5] 那行的 GPU 信息一起记下来。N1–N6 每步的输出复制给我。

## 第三部分:让 AI 走完整流程

1. 用 AI 应用打开 `lecture-summary-toolkit` 文件夹,说:
   > 用中文总结这节课:<合成字幕的完整路径>,单元 DEMO1001,日期 2026-01-01
2. 观察并记录:
   - AI 有没有用 `lsk.cmd`(或 `python ...\lsk.py`)而不是 `bash lsk`?它有没有因为找不到 bash 卡住?
   - 总结是否存到了 `总结\DEMO1001\` 下;AI 有没有跑 `lsk finish`,检查结果是 ✅ 还是 ❌。
   - 用记事本打开总结:中文正常;"章节时间线"里如果有链接,链接里是 `/` 不是 `\`。
   - `总结\DEMO1001\` 下生成了 `考点库.md`。这节课是用字幕跑的,`课程视频\` 里没有 `DEMO1001 2026-01-01.mp4`,所以**考点库里不应该有任何 `.mp4` 链接**,时间只是纯文字(比如 `36:00`,不带括号链接)。
   - `lsk finish` 的输出里没有 `SyntaxWarning` 或 `DeprecationWarning`。
3. 再用英文版测一次(`--lang en` 或者对 AI 说"Summarize in English"),看 `.en.md` 和 `Exam-Bank.en.md`。

## 第四部分:网页版

1. 打开 ChatGPT / Claude 网页版,新开对话,上传合成字幕。
2. 打开 `prompts\web-prompt.zh.md`(用记事本),全选复制,粘贴发送。
3. 记录:文件在记事本里是不是乱码;AI 有没有按固定结构输出。
