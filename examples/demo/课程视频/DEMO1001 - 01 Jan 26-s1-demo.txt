 the summary toolkit. So there is no copyright problem in sharing it. Today's topic is testing
 loops. Loops are surprisingly hard to test. The body of a loop can run zero times, exactly once,
 or many times, and each of those counts can hide a different fault. Line coverage tells you the
 but not how many times. So here is the informal heuristic that most teams use. Write one test
 where the loop body never runs, one where it runs exactly once, and one where it runs more than once.
 This is informal, but it catches a lot of off by one errors. The textbook formal eases this with
 prime paths. A simple path visits no node twice. A prime path is a simple path that cannot be extended
 without repeating a node. Prime path coverage subsumes node coverage and edge coverage.
 Let us look at a tiny example. While i is less than n, add a of i to the total and increment i with n
 equal to zero the body never runs. With n equal to one it runs once. With n equal to three it runs three
 times. Those three tests give you loop coverage. To summarize, test loop counts of zero, one and many,
 and use prime paths when you need something rigorous. The quiz next week will cover this slide deck,
 so make sure you can state the definition of a prime path. Thanks. See you next time.
